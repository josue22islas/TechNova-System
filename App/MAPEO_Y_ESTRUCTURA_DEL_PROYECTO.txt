12. REGLA DE SEPARACIÓN HTML / JAVASCRIPT / PHP
======================================================================

HTML:
- Solo estructura y atributos de conexión.
- No debe contener código PHP.
- No debe contener credenciales.

CSS:
- Solo presentación visual.
- No debe contener lógica ni datos del negocio.

JavaScript:
- Interacción del usuario.
- Solicitudes Fetch.
- Renderizado y estados visuales.
- Nunca contiene credenciales de MySQL.
- Sus validaciones mejoran la experiencia, pero no reemplazan PHP.

PHP:
- Autenticación y autorización.
- Validación definitiva.
- Lógica del negocio.
- Acceso a MySQL mediante consultas preparadas.
- Respuestas JSON; no genera las vistas HTML.

MySQL:
- Fuente persistente de datos.
- No es accesible directamente desde JavaScript.

13. CONVENCIÓN PARA RESPUESTAS JSON
======================================================================

Propuesta para endpoints nuevos:

Respuesta exitosa:

{
  "success": true,
  "data": {},
  "meta": {}
}

Respuesta con error:

{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Los datos enviados no son válidos.",
    "fields": {}
  }
}

Códigos HTTP previstos:

- 200: consulta o actualización correcta.
- 201: recurso creado.
- 204: operación correcta sin contenido.
- 400: solicitud incorrecta.
- 401: sesión inexistente o expirada.
- 403: usuario sin permiso.
- 404: recurso no encontrado.
- 409: conflicto de datos.
- 422: validación fallida.
- 500: error interno controlado.

Esta envoltura general todavía es [PLANIFICADA]. El contrato KPI existente se
mantiene como está hasta que se implemente el primer endpoint PHP.

16. SEGURIDAD DEL BACKEND
======================================================================

1. Las credenciales solo viven en PHP/configuración del servidor.
2. Cada endpoint protegido valida sesión.
3. Cada operación valida permisos del usuario.
4. SQL utiliza PDO y sentencias preparadas.
5. POST, PUT, PATCH y DELETE validan CSRF.
6. PHP valida todos los valores recibidos.
7. Las respuestas no revelan SQL, rutas privadas ni credenciales.
8. Las cookies de sesión deberán ser HttpOnly, SameSite y Secure cuando exista
   HTTPS.
9. JavaScript debe usar credentials: "same-origin" para sesiones del mismo
   origen.
10. Si frontend y API cambian a dominios distintos, CORS deberá configurarse
    explícitamente; actualmente no es necesario porque compartirán origen.
